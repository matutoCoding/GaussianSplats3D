# Degree-3 spherical harmonics tests

These tests validate the full 3rd-degree spherical harmonics (SH) pipeline added
to GaussianSplats3D: PLY parsing, ksplat export/import at every compression
level, shader evaluation, and the rotation used when scene transforms are applied.

## Run

```
npm test
```

## What each file does

- `generate-test-ply.js`
  Generates a synthetic binary PLY (INRIA V1 layout) whose splats carry full
  degree-3 SH with deliberately large degree-3 coefficients. A viewer that
  ignores degree 3 renders these as flat/greyish colors; a degree-3-aware one
  follows the angular reference.

- `cpu-sh-reference.js`
  CPU reference for the renderer's SH color evaluation. The basis polynomials
  and constants (`SH_C1`, `SH_C2`, `SH_C3`) are kept identical to the GLSL in
  `src/splatmesh/SplatMaterial.js`, so GPU and CPU share one convention.

- `degree3.e2e.test.js`
  End-to-end coverage of the three hard requirements plus the new chain:
  1. Legacy degree 0/1/2 ksplat files still load (byte layout and degree markers
     unchanged), reloaded through the public `KSplatLoader`.
  2. Public interfaces/parameters are untouched (the same generator/loader entry
     points are used).
  3. Degree 0..2 keep their exact historical `BytesPerSplat` (24/42/72 at
     compression level 1) and SH values round-trip on the original code paths.
  Plus degree-3 PLY parse -> ksplat export at compression levels 0/1/2 ->
  round-trip -> CPU reference color comparison across several view directions,
  asserting degree 3 materially changes the color versus a degree-2 truncation.

- `hardcoded-l2.js`
  Standalone copy of the pre-existing hard-coded l=2 SH rotation block in
  `SplatBuffer.rotateSphericalHarmonics5`, used as ground truth.

- `sh-rotation-reference.js`
  Numerically integrates SH rotation blocks over the unit sphere using the
  renderer's exact basis polynomials. Used for the l=3 band
  (`SplatBuffer.computeDegree3RotationBlock`). The integration takes the plain
  spatial rotation matrix (not the l=1 SH coefficient block), since the basis
  polynomials are functions of the spatial direction (x,y,z).

- `degree3-rotation.test.js`
  Rotation invariance for the scene-transform path. Rotating the SH coefficients
  by R and evaluating along direction d must equal the unrotated splat evaluated
  along R^-1 d. Checks every band (l=1/l=2 reach ~1e-9, l=3 ~1e-6, matching the
  numerical integration precision) and that a pure translation leaves the SH
  coefficients untouched.

- `validate-sh-rotation.js`
  Proves the numerical integration (a) matches the existing hard-coded l=2 block
  to ~1e-6 and (b) produces orthogonal rotation blocks for l=1, l=2 and l=3.

- `shader-regression.test.js`
  Compares the generated vertex shader for max SH degree 0/1/2 against a fixture
  captured from the pre-change `SplatMaterial`
  (`reference/SplatMaterial.reference.js`). The output is byte-identical, which
  guarantees lower-degree rendering cannot change.

- `reference/SplatMaterial.reference.js`
  Pre-change shader builder used by the regression guard. Its single import path
  is rewritten to point at the current `src/Constants.js`.

## Generated data

`data/degree3-scene.ply` is regenerated by `generate-test-ply.js` and is safe to
delete; the e2e test recreates it on every run.
